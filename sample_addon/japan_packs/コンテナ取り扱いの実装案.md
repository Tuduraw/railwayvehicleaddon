# コンテナ取り扱いの実装案(日本貨物パック向け・検討用)

コキ形式などのコンテナ車で、コンテナを積み下ろしできるようにする方法の比較と、アドオン側に専用機能を
実装する場合の設計案です。方針を決めていただくための資料で、まだ実装はしていません。

## 1. 既存の枠組みで代用する方法

| 方法 | できること | 問題点 |
|---|---|---|
| `ammo_parts`(弾数で部品を表示/非表示) | ダミー武器の弾数に応じてコンテナの部品を出し入れ。「補給」=積み込み | 下ろす操作が「発射」になる。中身(積荷)を持てない。武器扱いのためHUD・メニューに武器として出る |
| `toggle_parts`(キーで開閉する部品) | キー操作で全コンテナを一括表示/非表示 | 見た目だけ。個別の積み下ろし・中身は不可 |
| `runways`(空母の甲板) | なし(航空機の発着艦用で、コンテナには使えない) | — |
| 形式を分ける(現在の方式) | 「空車」「積車」を別形式で収録 | 積み下ろしは車両の置き換え。中身なし |

いずれも見た目の代用にとどまり、荷役(積み下ろし・中身)の表現はできません。

## 2. アドオンに専用機能を実装する案(推奨)

### 2-1. データ

- 車両JSON `rail.cargo_slots`(積載位置):
  ```json
  "cargo_slots": [
    { "x": 0.0, "y": 1.35, "z": -7.9, "length": 3.8, "accept": ["12ft"] },
    { "x": 0.0, "y": 1.35, "z": -3.95, "length": 3.8, "accept": ["12ft"] }
  ]
  ```
  31ftや20ftのように複数の区画をまたぐコンテナは、`length` の合計で載るかを判定します。
- コンテナの定義 `data/<namespace>/containers/<名前>.json`: 大きさの区分(12ft・20ft・31ft・40ft・タンク)、
  モデル・テクスチャ、収納できる量(インベントリの枠数)、空/満載時の重さ。

### 2-2. 遊び方

- **コンテナはアイテム**として持ち運べ、中身(インベントリ)を保持します(シュルカーボックスと同じ考え方)。
- **積み下ろし**は、駅に置く「コンテナ荷役機」ブロック(トップリフター・クレーン相当)で行います。線路区間に
  連結し(転てつてこ等と同じ連結モード)、停車中の列車の積載位置と、荷役機の保管枠との間でコンテナを移します。
  GUIでの手動操作と、レッドストーン入力での自動(全部積む/全部下ろす)を用意します。
- 手持ちのコンテナアイテムで車両の積載位置を右クリックして、直接積むこともできるようにします。

### 2-3. 実装の要点

- 積載状態は車両ごとに保存(位置ごとのコンテナ種類+中身)。クライアントへは種類だけを同期します
  (中身はサーバーのみ)。
- 表示は、アドオン側の描画処理で、車体の向き・傾きに合わせて積載位置にコンテナのモデルを描きます
  (信号機の灯火・転車台の桁と同じ方式)。
- 積んだコンテナの重さを車両の `mass` に加え、編成の加速に反映します(既存の重さの仕組みをそのまま使えます)。
- 同じ仕組みで、無蓋車・ホッパ車・タンク車の「ばら積み」(石炭・砂利・石油など)の積み具合の表示にも
  広げられます(積載位置の種類を `bulk` にする)。

### 2-4. 段階案

| 段階 | 内容 |
|---|---|
| 1 | コンテナの種類と積載位置・表示・荷役機での積み下ろし(中身なし) |
| 2 | コンテナの中身(インベントリ)、重さへの反映 |
| 3 | レッドストーンでの自動荷役、ばら積み車への拡張 |

## 3. 決めていただきたいこと

1. 既存の枠組みでの代用(現在の「空車/積車の別形式」)で十分か、専用機能を作るか
2. 専用機能の場合、コンテナに中身(アイテムの輸送)を持たせるか、見た目だけにするか
3. 荷役の操作(荷役機ブロック・手持ちアイテム・両方)
